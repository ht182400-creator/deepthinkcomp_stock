## 疑问 2：行情数据源——通达信 MCP 是否收费？

**客户疑问**：D2.1~D2.3 是否使用通达信 MCP？是否需要收费？

**调查结论**（2026-08-16 检索公开信息）：
- **通达信官方 MCP（txmcp.tdx.com.cn）为积分制收费**：新用户注册送 1 万通达信积分，约覆盖 1 个月查询量；活动结束后需按量购买积分
- 按积分分 5 档，覆盖 A 股/港股/基金/指数/期货期权 15 个工具
- 社区版 `tdx-mcp`（基于 eltdx TCP 直连）虽免费，但需本地通达信客户端配合，稳定性未经本项目验证

**对比**：

| 方案 | 成本 | 数据维度 | 稳定性 | 决策 |
|------|------|---------|--------|------|
| 通达信官方 MCP | 收费（积分制，仅送 1 万≈1 月） | 全（15 工具 5 档） | 官方 | ❌ 仅作最后备选 |
| 腾讯 qt.gtimg.cn | **免费** | 报价/分时/盘口 | 高 | ✅ **首选** |
| 东财 push2/datacenter | **免费** | 主力资金/财务/股东/新闻 | 中（需限流） | ✅ **兜底** |
| 通达信本地 .day | **免费** | 历史 K 全量（2001 至今） | 极高（0.01s） | ✅ **历史 K 首选** |
| npx westock | **免费** | 分钟 K 补全 | 中 | ✅ **离线补全** |

**决策**（D2/D3）：
- **主链：腾讯 → 东财 → 通达信本地 → npx 免费四级降级链**（沿用 deepthinkSingle 已验证方案）
- **通达信 MCP：第 5 级最后兜底**，默认关闭；仅在免费四级链全挂、且积分仍有剩余时启用

## 疑问 3：前端技术栈——Vue3 vs 原生 JS

**客户疑问**：Vue3 与"原生 ES Modules + ECharts"有哪些优劣势？

### 3.1 对比图（结论存档）

```
┌─────────────────────────────────────────┬─────────────────────────────────────────┐
│  原生 JS + ECharts（已定案）              │  Vue3 + Pinia + Router（备选）           │
├─────────────────────────────────────────┼─────────────────────────────────────────┤
│ ✓ 零构建链：改完刷新即用                  │ ✓ 响应式状态管理（Pinia）                 │
│ ✓ 源码=产物，易调试                       │ ✓ 组件化（SFC），可复用性高               │
│ ✓ deepthinkSingle 已验证 128 测试        │ ✓ 官方 Router 多页面支持                  │
│ ✓ 启动极快，无 node_modules               │ ✓ 生态大、招人容易、长期大型项目首选       │
│ ✓ 单人维护改动最直接                      │                                          │
│─────────────────────────────────────────┼─────────────────────────────────────────┤
│ ✗ 状态管理手写（全局对象）                │ ✗ 引入 Node 构建链（npm/vite/build）       │
│ ✗ 组件复用靠函数而非组件                  │ ✗ 项目体积×3（node_modules）              │
│ ✗ 页面多时模板逻辑易分散                  │ ✗ 现有 2 个老项目前端需全量重写            │
│ ✗ 多人协作无框架约束                      │ ✗ 构建报错排查成本高                      │
├─────────────────────────────────────────┼─────────────────────────────────────────┤
│ 适合：单人到小团队 · 快速迭代             │ 适合：多人团队 · 长期大型项目              │
│ 当前项目（1 人 · 8 Tab）完全够用          │ 当前场景属"杀鸡用牛刀"                    │
└─────────────────────────────────────────┴─────────────────────────────────────────┘
```

### 3.2 详细分析

**原生 JS + ECharts（推荐，已定案）**

| 优势 | 劣势 |
|------|------|
| ✅ **零构建链**：改完 JS 刷新即生效，无 npm install/build/报错排查 | ❌ 状态管理手写（全局对象/自定义事件，约 200 行内可覆盖） |
| ✅ **源码=产物**：打开 app.js 即实际运行代码，调试直接 | ❌ 组件化弱：DOM 操作易重复 |
| ✅ **deepthinkSingle 已验证**：ECharts 图表封装（minute/volfs/fund/kline）现成可搬 | ❌ 无虚拟 DOM：大列表需自节流/虚拟滚动 |
| ✅ 项目体积小（无 node_modules），启动即用 | ❌ 多人协作无框架约束 |
| ✅ 单人维护改动最直接 | |

**Vue3 + Pinia + Router（备选）**

| 优势 | 劣势 |
|------|------|
| ✅ 响应式状态管理：持仓/设置/轮询状态集中管 | ❌ **引入 Node 构建链**：npm/vite/打包 |
| ✅ 组件化（SFC）：模板/样式/逻辑内聚 | ❌ **老项目前端全量重写**（deepthinkstock + deepthinkSingle 均为原生 JS） |
| ✅ 官方 Router 天然多页面/路由守卫 | ❌ 体积膨胀（node_modules 数百 MB），部署多一层 |
| ✅ 生态大、招人容易、长期大型项目首选 | ❌ 当前场景属"杀鸡用牛刀" |

### 3.3 决策理由

1. **本质是本地个人工具**：单用户、本地行情、快速迭代——不是多人协作大型 SaaS
2. **deepthinkSingle 已验证**：原生 JS + ECharts 已做出完整行情系统（128 测试通过），直接复用成本最低
3. **规模匹配**：8 Tab + hash 路由 + 单页详情，手写状态管理 ≤200 行，不值得为它引入整套构建链
4. **留退路**：未来若做多用户 SaaS，后端 API 不变（前后端分离），仅重写前端层即可迁移 Vue3

**决策**（D4）：原生 ES Modules + ECharts + Chart.js（无构建链），hash 路由承接 `#/stock/<code>`。

## 疑问 4：刷新频率指什么？

**客户疑问**："行情刷新频率 5s/10s"是什么意思？

**分析**：个股详情页打开期间，行情价格每秒都在变，前端需周期性向服务器要新数据（轮询），不能只加载一次。

**对比**：

| 数据 | 刷新间隔 | 理由 |
|------|---------|------|
| 行情概况（现价/涨跌/换手/盘口） | **5 秒** | 交易决策最敏感，尽量实时 |
| 资金博弈/订单流 | **10 秒** | 变化相对慢，5s 浪费请求 |
| 财务/股东 | **10 分钟**（缓存） | 财报一天只变几次 |
| 新闻公告 | **30 分钟** | 公告低频 |

**为什么不全用 1 秒？** 每次轮询都打一次行情接口，太频繁会被数据源（腾讯/东财）限流甚至封 IP——这正是架构 `rate_limiter`（腾讯 5 次/s、东财 2 次/s）存在的原因。5s/10s 是"实时感"与"别被封"的折中。

**行为影响**：打开详情页挂着，5 秒后价格自动变；切走 Tab 后轮询自动停止（不浪费请求）。

**决策**（D6）：价格/盘口 5s；资金/订单流 10s；财务 10min 缓存；新闻 30min。

## 疑问 5：个股详情页范围——8 卡全量 vs 3 卡先交付？

**客户疑问**："详情页范围指什么？"

**分析**：详情页（`#/stock/xx`）本期做几个数据卡片。

**对比**：

| 卡片 | 内容 | 数据源 | 成本 |
|------|------|--------|------|
| ① 行情概况 | 现价/涨跌/换手/PE/PB/市值/量比等 16 指标 | 腾讯（免费）| 低 |
| ② 分时走势 | 240 根分钟线（白线+黄线） | 腾讯 ifzq | 低 |
| ③ 五档盘口 | 买1-5/卖1-5/委比/量比 | 腾讯 | 低 |
| ④ VOLFS 量能 | 每分钟量柱 红涨绿跌 | 腾讯→东财 | 中 |
| ⑤ 主力资金 | 主力净流入累计曲线 | 东财 push2 | 中 |
| ⑥ 资金博弈 | 主力/散户/大单副图 | 东财 | 中 |
| ⑦ 财务摘要 | 5 年营收/净利/ROE 柱状图 | 东财 datacenter | 中 |
| ⑧ 股东户数+新闻 | 户数趋势 + 最近 10 条公告 | 东财 | 低 |

| 选项 | 内容 | 优点 | 缺点 |
|------|------|------|------|
| **A 3 卡快速版** | ①②③ 行情概况+分时+盘口 | 最快上线 | "看行情"能力打折，且需拆掉已验证代码 |
| **B 8 卡全量版** | ①②③④⑤⑥⑦⑧ 全部 | deepthinkSingle 全部已验证可用，**迁移成本≈0** | 无实质缺点 |

**决策**（D7）：**8 卡片全量**——deepthinkSingle 的 8 卡全部开发完成并通过 128 测试，新项目只是搬运 + 加跳转，几乎不增工作量；只做 3 卡反而要拆代码。
