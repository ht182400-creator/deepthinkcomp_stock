## 1. 为什么只做这一条规则

| 规则 | 实测效果 | 结论 |
|---|---|---|
| 单票固定止损 -15% / -25% | 回撤**纹丝不动**（仍 -51.83%） | ❌ **不做** |
| 单票移动止损 -15% / -25% | 最好仅改善 0.55pp（ST1） | ❌ **不做** |
| 均线择时（上证 MA56 之下降仓/空仓） | 空仓 32.6% 时间，回撤仅改善 **0.19pp**，夏普 0.287→0.210 | ❌ **不做** |
| **组合回撤 -15% → 暴露减半** | 回撤 **-51.83% → -35.29%**，Calmar **+16%**，夏普几乎不变 | ✅ **做这个** |

**根本原因**：回撤来自**系统性下跌**（市场整体下挫，全部持仓一起跌），而不是个股踩雷。
单票止损只能"卖出后再买回"；均线择时滞后（指数跌破年线时组合已跌完）。
**只有组合层的仓位管理有效。**

> 另一个机制性发现：原策略在 `regime_scope='stock'` 下暴露**恒为 0.9** ——
> 个股级 regime 只做入场筛选，**完全没有市场层面的仓位管理**，这是 -51.83% 的根因。

## 2. 规则（精确表述）

**每周五收盘后执行一次**：

```
peak   = max(历史峰值总资产, 当前总资产)
总资产  = Σ(持仓市值) + 现金
dd     = 总资产 / peak − 1

dd > −15%   → 目标暴露 90%（正常持仓）
dd ≤ −15%   → 目标暴露 45%（减半）

若 当前持仓市值 > 总资产 × 目标暴露：
    需卖出金额 = 当前持仓市值 − 总资产 × 目标暴露
    各持仓按市值占比等比卖出（股数取整到 100 股）
```

**恢复**：dd 回到 −15% 以上时，目标暴露自动回到 90%（可加回仓位）。

**阈值选择依据**（阈值扫描）：

| 阈值 | 年化 | 夏普 | 最大回撤 | Calmar |
|---|---|---|---|---|
| -10% | 5.05% | 0.194 | -35.29% | 0.143 |
| **-15%** | **6.58%** | **0.274** | **-35.29%** | **0.186** ← 最优 |
| -20% | 7.01% | 0.282 | -38.77% | 0.181 |
| -25% | 5.55% | 0.192 | -43.16% | 0.129 |
| -30% | 7.00% | 0.256 | -43.16% | 0.162 |

> 过紧（-10%）年化损失过大；过宽（-25%/-30%）触发太晚，回撤反而恶化到 -43%。

## 3. 数据准备（一次性）

| 数据 | 位置 | 说明 |
|---|---|---|
| 持仓 | `data/holdings.json` | 录入 `code` + `amount`（投入金额） |
| 现金 | `data/settings.json` 的 `cash` | **买入后手工扣减**；卖出后加上 |
| 风控状态 | `data/portfolio_state.json` | 首次运行自动生成 |

**股数自动推算（零录入负担）**：首次见到某持仓时，系统用**当时最新价**记为 `entry_price`，
之后按 `股数 = amount / entry_price` 推算市值 → **无需手工录股数**。

## 4. 每周操作步骤

1. 按原有流程生成本周买仓清单；
2. **收盘后运行**：`python -m panels.portfolio_guard`；
3. 看输出里的 `target_expo`：
   - `0.9` → 按原计划操作；
   - `0.45` 且 `advise` 非空 → **执行减仓**；
4. **手工执行**（按 `advise` 列表逐只卖出指定股数）；
5. 更新 `data/settings.json` 的 `cash`（卖出金额加进去）。

## 5. 减半的具体执行示例

**假设**：

| 持仓 | 投入金额 | 入场价 | 股数 | 现价 | 市值 |
|---|---|---|---|---|---|
| 测试甲 | 30,000 | 15.00 | 2,000 | **11.00** | **22,000** |
| 现金 | — | — | — | — | 20,000 |
| **合计** | | | | | **42,000** |

历史峰值 `peak = 50,000` → `dd = 42,000/50,000 − 1 = **−16%**` → **触发降仓**。

**计算**：

| 步骤 | 计算 | 结果 |
|---|---|---|
| 目标持仓市值 | 42,000 × 45% | **18,900 元** |
| 需卖出金额 | 22,000 − 18,900 | **3,100 元** |
| 占持仓比例 | 3,100 / 22,000 | **14.1%** |
| 应卖股数 | 3,100 / 11 = 281.8 股 | → 取整 **3 手 = 300 股** |

**执行结果**：

| 项目 | 减仓前 | 减仓后 |
|---|---|---|
| 测试甲持仓 | 2,000 股 × 11 = 22,000 | **1,700 股 × 11 = 18,700** |
| 现金 | 20,000 | **23,300** |
| 总资产 | 42,000 | **42,000**（不变，忽略手续费） |

> 整手取整会带来少量偏差（本例多卖 200 元），可接受。
>
> **减仓后 peak 不下调** —— 后续判断仍以 50,000 为峰值，直到净值创新高。

## 6. 注意事项与局限

| 事项 | 说明 |
|---|---|
| **判断频率** | **周频**（与回测一致）。不要日内频繁切换，否则偏离回测口径且交易成本上升 |
| **执行滞后** | 回测假设"当期调仓"，实盘是"周末判断、下周执行"，滞后约 1 周 → **实盘效果可能略差于回测** |
| **出入金** | 入金会使总资产跳升、回撤假性恢复 → 出入金后执行 `reset_peak()` 重置峰值 |
| **`cash` 维护** | 目前依赖手工维护（买入扣减、卖出增加）；忘记维护会导致总资产失真、风控误判 |
| **`entry_price` 偏差** | 首次运行时若已持仓较久，用"当时价"反推股数会有偏差 → 可手工修正 `portfolio_state.json` 的 `entry_price` |
| **未达目标** | 回撤只压到 **-35.29%**，**未达 -30%** 目标（见 §8 分档降仓） |
| **并非免费** | 年化牺牲 1.72pp（8.30% → 6.58%）。**若你能承受 -52% 回撤，可不开** |
