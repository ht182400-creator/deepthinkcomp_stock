## 0. 自审结论摘要

**原方案（R0~R12）方向正确，但有 4 个问题若不修，会导致"改了很多、收益没提升、甚至白做"。**

| 级别 | 编号 | 隐患 | 后果 | 修法 |
|---|---|---|---|---|
| 🔴 高危 | **H1** | **前复权导致回测不可复现** | 每次除权，历史价格全变 → 同一策略两次回测结果不同，无法归因、无法对比基线 | 回测改用**后复权**或**冻结复权基准 + 价格面板落盘** |
| 🔴 高危 | **H2** | **宇宙未随 R1 同步扩容** | R1 把财务源换成 gpcw（5561 只），但宇宙仍是 `fundamentals_broad.json`（1771 只）→ 数据升级白做 2/3 | **R1 阶段就把宇宙改为"扫描 lday"**，R7 只补退市股财务 |
| 🔴 高危 | **H3** | **落盘格式与范围未定清** | 40 字段 × 148 期 × 5561 只用 JSON ≈ 1~2GB；若只落最新期则**回测无法使用新因子** → 回测与实盘再次分裂 | 落 **Parquet 双文件**：`panel_history`（回测）+ `latest`（实盘） |
| 🔴 高危 | **H4** | **"最新期不完整"未进实现要点** | 季报披露期内（如 10 月），`gpcw20260930` 只填了一部分股票 → 统一取"全市场最新期"会让大批股票因缺数据被剔除，买池骤减 | 实盘按**每股回溯其最近有数据的报告期**，而非统一取最新期 |
| 🟠 中危 | H5 | R2 硬约束与 R5 资金利用率**互相伤害** | 候选少时强制"单行业 ≤1 只"→ 只能建 2 仓 → 利用率反而下降，与 R5 目标冲突 | R2 改**软约束**（分散度惩罚优先，硬上限兜底） |
| 🟠 中危 | H6 | R6 改评分**破坏前端契约** | `build_cards` 的 `score` 字段前端在渲染，历史 `action_log` 的分数也不可比 | 保留旧字段，**新增** `score_v2` + `breakdown`，前端并行展示一期 |
| 🟠 中危 | H7 | R8 改成交口径**摧毁 M3 对比基准** | R8 之后所有历史指标都变，R7 的"含退市股 vs 不含"对比失去参照 | R8 前**冻结当前基线快照**，R8/R7 后同时输出"新口径 / 旧口径"两套指标 |
| 🟠 中危 | H8 | R7 的**前置验证排在 W5** | 若验证失败（覆盖率 <60%），已投入 3 人日才发现要降级 | 前置验证**提前到 W1**（0.25 人日，纯脚本） |
| 🟠 中危 | H9 | **人工操作的滑点被低估** | 方案按量化假设（单边 0.12%）设成本；人工下单小盘股滑点常达 0.3%~0.5% | R8 成本参数按**人工场景**重设（滑点 0.3%，最低 5 元佣金） |
| ⚪ 遗漏 | H10 | **无组合级熔断** | R3 是个股止损；4 只票同时跌 15% 会同时触发 4 次止损 = 事实清仓，但无明确组合逻辑 | 新增 **R14 组合回撤熔断** |
| ⚪ 遗漏 | H11 | **无换手约束** | 为提利用率（R5）可能增加换手，人工执行成本与税负上升 | R5 加"单周换手上限" |
| ⚪ 遗漏 | H12 | **无策略失效监控**（最要命） | 系统失效后无人知晓，会一直按失效信号亏钱 | 新增 **R13 健康度监控**（滚动 IC / 滚动夏普 / 买入后 20 日胜率） |
| ⚪ 遗漏 | H13 | **字段映射未版本化** | 40 个列名硬编码在代码里；`gpcw` 更新导致列名变化时**静默取空值** | 字段映射落盘 `field_map.json`（带版本）+ 启动断言 |

**一句话**：原方案解决的是"**数据够不够、规则全不全**"，自审补的是"**结果可不可信、失效知不知晓**"。后者其实更重要。

## 1. 高危隐患详解

### 🔴 H1：前复权 → 回测不可复现（最深层的问题）

**现象**：`read_qfq()` 的 docstring 明确写着：

> 前复权锚定最新交易日: 末根 close 严格等于未复权末收

**这意味着**：每一次新的除权除息事件（分红、送转、配股）发生后，**全部历史价格都会被重新计算**。

**后果（严重）**：

| 场景 | 后果 |
|---|---|
| 同一策略、同一参数，相隔一个月跑两次回测 | **结果不同**（因为期间有股票除权，历史价格变了） |
| R8 改成 t+1 开盘成交后与旧结果对比 | 差异里混入了"复权基准漂移"，**无法区分是改动效果还是复权噪声** |
| R7 的"含退市股 vs 不含"对比 | 两组数据如果不在**同一复权基准**下生成，对比无意义 |
| 未来想做 walk-forward 验证 | 每一折的"历史"都在变，验证失去意义 |

**修法（三选一，建议 C）**：

| 方案 | 做法 | 评价 |
|---|---|---|
| A 用后复权 | 后复权锚定"上市首日"，新除权**不改变历史价格** | 最干净，但需改 `read_qfq` 的锚定逻辑 |
| B 冻结复权基准日 | 记录 `qfq_base_date`，回测固定用该日的因子表 | 需额外存因子表 |
| **C 价格面板落盘（推荐）** | 把**复权后的价格面板**连同 `base_date` 一起落盘为 Parquet，回测**只读快照**、不重算 | **一箭三雕**：同时解决 H3（落盘格式）、回测提速（不再每次重算宇宙）、可复现性 |

> **C 方案与原计划天然契合**：R1 本来就要落盘财务面板，把**价格面板**一起落盘即可。落盘时记录 `base_date`（复权基准日）、`tdx_version`（数据版本）、`field_map_version`，实现"回测可复现"。

### 🔴 H2：宇宙未随 R1 同步扩容（数据升级打三折）

**现状链路**：

```
宇宙来源  = fundamentals_broad.json  → 1771 只        ← 窄
财务来源  = cw/gpcw*.dat             → 5561 只（R1 改） ← 宽
```

**问题**：R1 只换财务源、不换宇宙 → 5561 只的财务数据里，**只有 1771 只能进候选池**，升级价值损失约 68%。

而且这会造成**中间态不一致**：

| 阶段 | 宇宙 | 财务源 | 状态 |
|---|---|---|---|
| 现在 | 1771 | 东财年报 | 基线 |
| **R1 后** | **1771** ❌ | **gpcw 5561** | ⚠️ 数据宽了但宇宙没宽，指标变化不大 → 容易误判"R1 没效果" |
| R7 后 | 5561+退市 | gpcw + baostock | 才真正到位 |

**修法**：把"宇宙构建改为扫描 `vipdoc/{sh,sz,bj}/lday/*.day`"（原 R7 的步骤 1）**提前到 R1**。

- R1 之后：宇宙 = lday 扫描（含指数/基金过滤）∩ 有 gpcw 财务 → 约 5561 只
- R7 只做"给退市股补 baostock 财务"，不再动宇宙

**副产品**：这一步做完，回测的候选池从 1771 → 5561，**策略表现会有实质变化**（正面或负面都需观察）——这才是 R1 真正的价值所在。

### 🔴 H3：落盘格式与范围未定清

**问题**：R1 说"落盘 ≈40 个字段"，但没回答两个关键问题：

1. **落最新期还是全历史？**
   - 只落最新期 → **回测用不了新因子** → 回测与实盘口径再次分裂（重演当前"回测有 ind_cap、实盘没有"的老毛病）
   - 落全历史 → 数据量大

2. **什么格式？**
   - JSON：40 字段 × 148 期 × 5561 只 ≈ **3300 万数值** → JSON 约 **1~2 GB**，读取慢
   - Parquet：同样数据压缩后约 **50~100 MB**，读取快 10~100 倍

**修法**：**Parquet 双文件**

| 文件 | 内容 | 用途 | 规模 |
|---|---|---|---|
| `data/panel_history.parquet` | 148 期 × 5561 只 × ~40 字段 | **回测** | 压缩后约 50~100MB |
| `data/panel_latest.parquet` | 最新可用期 × 5561 只 | **实盘**（快） | 几 MB |
| `data/price_panel.parquet` | 复权后价格面板（OHLCV）+ `base_date` | 回测 + 解决 H1 | 视周期而定 |

依赖：`pandas`（已有，mootdx 依赖）+ `pyarrow`（需新增，纯 Python 轮子）。

### 🔴 H4：最新期不完整 —— 必须"按股票回溯"

**实测依据**：查询 `gpcw20250630.dat` 的中间状态时曾只返回 **114 只**；而最终态是 5517~5561 只。说明**季报披露期内，该报告期文件是逐步填充的**。

**后果**：实盘取数时若"统一取全市场最新报告期"：

- 10 月中（三季报披露期）取 `gpcw20260930` → 可能只有几百只有数据
- 其余 5000 只因"最新期无财务"被质量门剔除 → **买池骤减甚至为空**

**修法**：质量门取数改为**每股回溯**：

```
对每只股票：从最新报告期向前找，取"该股自己最近一个有完整数据的报告期"
→ 若该报告期距"应披露期"超过 2 期 → 标记 stale，降权/剔除
```

同时记录每只股票的 `fund_report_date`，在买仓清单中展示"财报截至期"，让用户能识别谁的数据陈旧。

> ⚠️ 此条**必须进 R1 的实现要点**（当前遗漏）。

## 2. 中危隐患详解

### 🟠 H5：R2 硬约束 vs R5 资金利用率（互相伤害）

**冲突推演**（以 2026-09-04 真实数据为例）：

- 合格池 7 只，其中 **4 只集中在科创板 688**
- R2 规则"单板块 ≤2" → 只能选 2 只 688 + 其他行业的
- 但其他行业只有 3 只可选，且价格可能超预算
- 结果：**可能只建 2 仓** → 资金利用率从 70.6% 进一步降到 ~45%
- 与 R5（目标 ≥95%）**直接冲突**

**修法：把"硬约束"改为"软约束 + 硬上限兜底"**

| 层 | 规则 | 说明 |
|---|---|---|
| 首选（软） | 已入选行业中再选同行业股 → **分数 × 0.85 惩罚** | 实现"优先分散"而非"禁止同行" |
| 兜底（硬） | 单板块 ≤2、单行业 ≤2（放宽到 2） | 仅在极端集中时生效 |
| 提示 | 约束导致持仓数 < N 时 → 明确提示"建议放宽约束或降低 N" | 避免静默少建仓 |

> 更根本的解法：**H2 修好后宇宙扩到 5561 只**，候选变多，约束才不至于伤持仓数。**所以 H2 必须先行。**

### 🟠 H6：R6 改评分会破坏前端契约

`modules/holdings/holdings.py` 的 `build_cards()` 产出 `score` 字段，被前端与 `/api/report/md` 共用；历史 `action_log.json` 也存了旧评分。

直接替换评分算法 → 前端渲染异常、历史记录不可比。

**修法**：并行双轨一期

```python
card.update(
    score=old_score,              # 保留，前端继续用
    score_v2=new_score,           # 新增
    score_breakdown={...},        # 新增（归因）
    stale_months=…,               # 新增（财报时效）
)
```

前端先展示 `score_v2` + 归因；确认稳定后再移除 `score`。

### 🟠 H7：R8 改成交口径会摧毁对比基准

R8 把成交价从"t 周收盘"改为"t+1 周开盘"，**所有历史指标都会变**。而 M3 验收要求输出"含退市股 vs 不含"的对比表 —— 如果两组数据的成交口径不同，对比无效。

**修法**：在 R8 动工**之前**先做一次"基线冻结"：

1. 冻结当前 `results_layer2_fresh.json` 为 `baseline_legacy.json`（注明口径：t 周收盘、无退市股、无成本细化）
2. R8 完成后重跑 → `baseline_new_cost.json`
3. R7 完成后重跑 → `baseline_new_cost_delisted.json`
4. 三层对比表才能**逐项归因**：口径变化贡献多少、退市股贡献多少

### 🟠 H8：R7 前置验证排期过晚

原方案把"验证 baostock 覆盖率"放在 R7 内部（W5）。若覆盖率不达标，前面已投入 3 人日才发现要降级。

**修法**：前置验证提为**独立小任务，排在 W1**（0.25 人日，纯脚本，读 baostock 抽样 10~20 只退市股）。**早死早超生。**

### 🟠 H9：人工操作的滑点被低估

原方案的 0.12% 单边成本来自量化假设。而**人工下单**的现实：

| 项 | 量化假设 | 人工现实 |
|---|---|---|
| 滑点 | 0.02%~0.05% | **0.1%~0.3%**（小盘股更差） |
| 佣金 | 万 2.5（无最低） | **万 2.5 但有最低 5 元** |
| 印花税 | 0.05%（卖出） | 同 |
| 时间成本 | 无 | 挂单等待、错过价格 |

**修法**：R8 成本参数按人工场景重设 —— `SLIPPAGE = 0.002`（0.2%）、`MIN_COMMISSION = 5.0`、`STAMP_TAX = 0.0005`（卖出）。**宁可比现实悲观，也不要用乐观假设自欺。**

## 3. 遗漏项（原方案没有的）

### ⚪ H10 / 新增 R14：组合级回撤熔断

R3 是**个股**止损。但 2~4 只组合在系统性下跌中会**同时触发**，等于一次性清仓 —— 这个行为需要被显式设计，而不是"恰好发生"。

| 规则 | 阈值（建议） | 动作 |
|---|---|---|
| 组合从高点回撤 | > 15% | 降至半仓（新建仓暂停） |
| 组合从高点回撤 | > 25% | 清仓观察，需人工确认后重启 |

### ⚪ H11 / 并入 R5：换手约束

为提升资金利用率（R5）可能增加调仓频率，但**人工执行的成本与税负是真实的**。

- 加 `MAX_TURNOVER_PER_WEEK = 0.5`（单周换手上限 50%）
- 若超限，**优先保留已有持仓**、延后新建仓

### ⚪ H12 / 新增 R13：策略失效监控（**最重要的一项**）

原方案全部是"怎么把系统做得更好"，**没有一条是"怎么知道系统坏了"**。

对 10~15 万的人工账户，最危险的不是"少赚 2%"，而是**策略已失效却继续按信号交易**。

**建议监控项**（滚动窗口，落盘时序 + 前端展示）：

| 指标 | 窗口 | 警戒线 | 含义 |
|---|---|---|---|
| 滚动 IC（因子 vs 未来 4 周收益） | 26 周 | < 0.01 连续 8 周 | 因子失效 |
| 滚动夏普 | 52 周 | < 0 | 策略处于水下 |
| 买入后 20 日胜率 | 滚动 30 笔 | < 45% | 信号质量下降 |
| 买池规模 | 周 | < 3 只 | 市场不适合 或 质量门过严 |
| 财报数据新鲜度 | 实时 | 超期 > 2 期占比 > 20% | 数据源问题 |

**告警方式**：超过警戒线时在首页显示醒目横幅 + 写入 `action_log`。

> 这一项建议**排在最前面之一**：因为它同时是"R1~R8 改动的效果验证器"（改完到底有没有用，靠它回答）。

### ⚪ H13：字段映射版本化

R1 要抽取 40 个中文字段名。`gpcw` 一旦更新（通达信版本升级）导致列名变化：

- 若代码是**硬编码列名** → 静默取到 NaN → 质量门把全市场剔除 → **买池为空**（而非报错）
- 这是最危险的失败模式：**静默失效**

**修法**：

1. 字段映射落盘 `data/field_map.json`：`{"FN242": {"name": "股东人数(户)", "ver": "2026-09"}}`
2. 启动时**断言所有映射列存在**，缺列立即 `log.error` + 拒绝启动分析（不静默降级）
3. 记录 `gpcw` 数据版本（文件 mtime + 报告期清单的 hash）
4. 每个落盘面板带 `meta`：`{base_date, tdx_version, field_map_version, row_count}`

## 4. 更优方案建议

### B1（对应 H1+H3）价格与财务面板用 Parquet，双文件 + 带 meta

一次性解决"可复现、可回测、格式膨胀"三个问题。落盘结构建议：

```
data/panel/
├─ price_history.parquet      # 复权后 OHLCV 面板（周频+日频）
├─ fund_history.parquet       # 148 期 × ~40 字段
├─ fund_latest.parquet        # 最新可用期（实盘）
├─ field_map.json             # 字段映射（带版本）
└─ meta.json                  # {base_date, tdx_version, field_map_version, built_at}
```

### B2（对应 H5）R2 改软约束

分散度惩罚（× 0.85）+ 板块硬上限 ≤2，替代"单行业 ≤1"的一刀切。

### B3（对应 R10）因子 IC 快检提前

原方案把 IC 诊断放在 Backlog。建议**提前到 R1 之后，只花半天**：

- 用现有 5 因子 + 新拿到的 9 个成长因子，各算一次"与未来 4 周收益的 IC / IR"
- 目的：用半天回答"这些因子到底有没有用"，**避免在无效因子上投入数周**
- 若某因子 IC 长期为 0 → 直接从评分卡剔除，权重省下来给有效因子

### B4 采用"最小验证闭环"而非"任务清单"

原方案是 6 周铺开 R0~R9，风险是"改完一堆但不知道有没有用"。

**建议改为假设-验证节奏**：

| 阶段 | 动作 | 验证问题 |
|---|---|---|
| 第 1 周 | R1（数据层：面板落盘 + 宇宙扩容） | **新数据是否让回测指标发生实质性变化？变化方向是否合理？** |
| 第 1 周末 | 跑一次"新旧数据对比回测" | 若几乎无变化 → 停下来查原因（可能宇宙没扩、可能字段取错） |
| 第 2 周 | R4 + R2 软化 + R3/R0 | 组合是否真的更分散、资金利用率是否上来 |
| 第 3 周 | R8 口径修正 + 基线三层对比 | 成本与退市股各贡献多少 |
| 后续 | R6 评分卡 + R13 监控 | 评分区分度是否改善 |

**关键差异**：每个阶段都有**明确的验证问题**和**"不达标就停"的判据**，而不是"按清单做完再说"。

### B5 成本参数按人工场景设定（对应 H9）

见 H9。

### B6 R6 用"分位合成"而非"原始值加权"

不同维度量纲不同（ROE 是百分比、动量是收益率、流动性是金额），**直接加权会被量纲大的维度主导**。

正确做法：每个维度先算**截面分位（0~1）**，再加权合成。原方案隐含了这点，但需在实现要点中**显式写明**，否则容易写错。

## 6.5 W1 验收结果（2026-09-11 实测）——**数据升级导致业绩下降**

> 这是"假设-验证式推进"（B4）的第一次实践，**它避免了一次会让实盘业绩腰斩的上线**。

### 6.5.1 实验设计（分解归因）

用同一引擎、同一参数（方案 B / N=15 / 起 2014-01-01），仅改变数据口径，逐步隔离贡献：

| 实验 | 财务口径 | 宇宙 | 隔离的变量 |
|---|---|---|---|
| **E1** | 年报（旧） | 1689 只（旧，`fundamentals_broad`） | 基线 |
| **E2** | **TTM**（新） | 1689 只（同 E1） | E2 − E1 = **财务时效**贡献 |
| **E3** | TTM | **5387 只**（新，面板全市场） | E3 − E2 = **宇宙扩容**贡献 |

### 6.5.2 结果

| 实验 | 年化 | 夏普 | 最大回撤 | 空仓 | 换手 | 均池 |
|---|---|---|---|---|---|---|
| **E1** 年报+旧宇宙 | **13.07%** | **0.449** | **-44.50%** | 0.0% | 30.18% | 96.2 |
| **E2** TTM+旧宇宙 | 9.75% | 0.316 | -43.59% | 0.0% | 31.10% | 102.8 |
| **E3** TTM+全宇宙 | **6.58%** | **0.182** | **-55.34%** | 0.0% | 31.44% | 203.6 |
| **E1 → E3 合计** | **−6.49pp** | **−0.267** | **−10.84pp** | — | +1.26pp | +107.4 |

**两项改动都是负贡献**：

- 财务时效（TTM）：年化 −3.32pp，夏普 −0.133，回撤 **改善** 0.91pp
- 宇宙扩容：年化 −3.17pp，夏普 −0.134，回撤 **恶化 11.75pp** ← 最严重

### 6.5.3 诊断：旧宇宙隐含了一个"未被建模的因子"

**根因**：旧宇宙 ``fundamentals_broad.json``（1771 只）来源是 **CSI300+500 + 宽池**，
天然**偏向大中盘**；而新宇宙是全市场 5387 只，**包含大量小盘股**。

这带来两个后果：

1. **回撤恶化 11.75pp**：小盘股波动大、下跌深 → 组合回撤被显著放大；
2. **收益下降**：小盘股的"质量+动量"信号噪声更大，且均池从 103 只暴增到 204 只 →
   在同一分数阈值下，**选出的股票质量被稀释**（第 15 名与第 100 名一起竞争）。

> 换言之：**旧宇宙一直在免费充当"规模/流动性过滤器"**，但它没有出现在任何代码或公式里。
> 拿到"更全的数据"后该过滤器消失，暴露了策略的真实缺陷 —— 这正是
> [08 §2.5](./08-策略与架构评审报告.md) 所指出的"**无市值因子、无流动性约束**"。

### 6.5.4 结论与下一步

**结论**：**"数据更全" ≠ "策略更好"**。全市场宇宙本身不是优势，
**必须配套显式的规模 / 流动性约束**才能把"覆盖更全"转化为收益。

**不能做**：直接把宇宙切到全市场（会让实盘业绩腰斩）。

**下一步（新增 R2b，P0）**：加入规模 / 流动性过滤，把"隐含因子"显式化：

| 过滤项 | 建议阈值 | 依据 |
|---|---|---|
| 总市值下限 | ≥ 50 亿（或剔除最小 30% 分位） | 恢复大盘偏好，但**显式可控** |
| 日均成交额下限 | ≥ 5000 万 | 排除流动性陷阱（人工下单尤需） |
| 剔除 ST / 退市整理 | 名称含 `ST`/`退` | 风险排除 |

**验证方法**：在 E3 宇宙上叠加规模过滤（E4），
**若 E4 恢复到 E1 水平或更好 → 证明"覆盖更全 + 显式约束"优于"窄宇宙 + 隐含约束"**，
这才是真正的数据升级价值。

**方法论价值**：本次验收直接避免了一次"上线后业绩腰斩"的事故。
**这正是自审文档 B4（假设-验证式推进）的价值所在。**

### 6.5.5 E4 追加实验：规模/流动性过滤**未能**恢复 E1（2026-09-11）

按 §6.5.4 的计划实现 **R2b**（`backtest_bridge.build_liquidity_universe`），
用**回测起点前 52 周**的日均成交额定池（无前视），叠加在 E3 之上：

| 实验 | 定池规则 | 宇宙 | 年化 | 夏普 | 最大回撤 | 换手 | 均池 |
|---|---|---|---|---|---|---|---|
| **E1** | 旧宇宙（基线） | 1689 | **12.73%** | **0.421** | **-44.50%** | 29.79% | 96.4 |
| **E3** | 全宇宙（TTM） | 5387 | 6.26% | 0.162 | -55.69% | 31.21% | 203.8 |
| **E4a** | 日均成交额 ≥ 5000 万 | 1084 | **3.47%** | **0.069** | -48.88% | 29.02% | 67.6 |
| **E4b** | 日均成交额 ≥ 1 亿 | 550 | 4.42% | 0.123 | -48.90% | 25.02% | 33.4 |
| **E4c** | 日均成交额 ≥ 2 亿 | 287 | 3.38% | 0.076 | -48.05% | 24.10% | 17.3 |

**结论：❌ "旧宇宙隐含规模因子"这一假设被证伪。**

- 三个流动性档位**无一**恢复到 E1（最好也只有 4.42% vs 12.73%）；
- 回撤虽从 E3 的 -55.7% 改善到约 -48%，但仍差于 E1 的 -44.5%；
- **过滤越严反而越差**（E4c 仅 287 只、均池 17.3 ≈ N=15，等于无选择余地，质量因子被架空）。

**因此需要重新解释 E1 的优势来源**（现有三个候选假设，均未验证）：

| 假设 | 说明 | 验证方式 |
|---|---|---|
| H-A 隐含质量筛选 | `fundamentals_broad.json` 由 `fetch_fund_broad` 抓取，可能只包含"有完整财务数据"的股票 → 隐含质量过滤 | 检查其纳入标准；用同标准筛全市场复现 E1 |
| H-B 样本内过拟合 | E1 的 12.73% 可能来自参数在同一窗口上挑选（`N=15 / 5:5 / ROE≥10%` 均为人工设定） | **Walk-forward 分窗口**重跑，看稳定性 |
| H-C 板块构成差异 | 旧宇宙可能在某些板块（如科创板）占比显著不同 | 对比两宇宙的板块/行业分布 |

**转向决定（重要）**：既然"工程侧的数据升级"已被证明**不能自动转化为收益**，
后续优先级应从"继续做数据工程"**转向因子研究**：

1. **R10 因子 IC 诊断提前**（原为 Backlog）：用面板的 62 个字段，逐因子计算
   IC / ICIR / 分位组合收益，回答"**到底哪些因子有效**"；
2. 基于 IC 结果重构 **R6 Scorecard 2.0**，而非继续修补"质量 5 : 动量 5"的人工权重；
3. **暂停**把宇宙切换到全市场（E1 配置优胜，在原因查清前保持不变）。

**① E1 的稳健性远超全部对照组 —— H-B"单点依赖"维度不成立**

|---|---|---|

**结论：E1 的 12.73% 不是靠某一年撑起来的。**

**② 2023 年是最大分歧点（E1 +32.94% vs E4 全线 -11%~-14%，差约 44pp）**

2023 年是"中特估 + AI"行情。E4 系列在该年**全线亏损**，而 E1 大赚。
原因推断：E4 的合格池被压缩到 17~68 只（vs E1 的 96 只），**接近 N=15 时几乎无选择余地**，
质量因子被架空，组合被动量因子主导 → 在风格剧烈切换年份被"追高杀跌"。

**③ E1 在 2024 年"逆势正收益"（+3.38% vs E3 的 -17.55%）——防御性证据**

2024 年初小微盘流动性危机（量化/雪球爆仓，中证 2000 大幅回撤）。E1 **+3.38%**、
E4 系列 +1.69%~+5.72%，而 E3（全宇宙）**-17.55%**。
→ 说明**排除小微盘**确有防御价值，但价值来自"避开尾部"而非"提升收益"。

**④ E3 在 2025 年反超（+44.54% vs E1 的 +23.27%）**

2025 年小微盘修复，全宇宙弹性更大。**这类收益稳健性差**（涨得快、也更易回吐，见 2026 年）。

| **H-B** 样本内过拟合 | ⚠️ **"单点依赖"维度已排除；"参数同窗口挑选"维度待验** | 分年 9/13 正收益、剔除最好年 9.19% → **不是单点依赖**。但 `N=15 / 5:5 / ROE≥10% / mom=52` 仍是全样本上人工设定的，**需 walk-forward 滚动重估**才能完整回答 |
| **H-C** 板块构成差异 | ⏳ **顺手可做（约 0.5 天）** | 未验证。可直接对比两宇宙的行业/市值分布 |

#### 6.6.4 重大发现：**R1（季报 TTM 化）方向需要反转**

同宇宙下的干净对比（E1 vs E2）：

| 口径 | 年化 | 夏普 | 最大回撤 |
|---|---|---|---|
| **年报（E1）** | **12.73%** | **0.421** | **-44.50%** |
| **TTM（E2）** | 9.75% | 0.30 | -46.49% |

**同宇宙下，TTM 反而使年化下降约 3.3pp。** 说明原 R1 的假设（"因子越及时越有效"）**不成立**。

**原因推断**：

| 因素 | 说明 |
|---|---|
| 季报**未经审计** | 质量因子（ROE / FCF）的核心价值在于"可信"，未经审计的季报噪音显著更大 |
| TTM 平滑效应 | 滚动 TTM 削弱了年报中"真实盈利水平"的区分度，反而使门槛更易通过 |
| 门槛漂移 | `ROE≥10%` 在年报口径下筛出 96 只；TTM 口径下筛出 203.8 只（全宇宙）→ 门槛实质性放宽，混入更多噪音标的 |

**修正后的用法建议**：

| 用途 | 数据源 | 理由 |
|---|---|---|
| **质量水平**（ROE / FCF / 负债率） | **年报（经审计）** | 可信度优先 |
| **变化检测**（营收/利润增速、拐点） | **季报** | 时效性优先，用于**成长因子**而非替换质量因子 |
| **风控**（爆雷预警） | **最新季报** | 快速识别恶化，但仅作减仓信号，不作选股加分 |

> **即：季报的正确用法是"做减法和预警"，不是"做加法和选股"。**

**因此 R1 需重新定位**：从"P0 第一优先改造"降级为"**可选 + 默认关闭**"
（`FUND_SOURCE` 保留切换能力，默认走年报），其价值主要体现在**风控预警**而非收益。

**§6.5/6.6 最终结论**：

> 数据面板（R1/R1a）的收益是**工程性**的（数据更及时 / 更全 / 可复现 / 一次拿到 62 字段），

**真实回撤比含前视版本差 10pp 以上** → 这比收益的高估**更危险**（因为回撤直接决定能否坚持执行）。

> **`R300_dyn`：年化 8.30% / 夏普 0.287 / 最大回撤 -51.83% / Calmar 0.16**

#### 6.11.5 结论与方向

1. **原基线 12.73% 确认作废**；真实水平为 **6.7%~8.3%**（滚动池）、**4%~6%**（静态池下限）；

### 6.12 R3 风控实验（E7 / E8）—— **单票止损与市场择时无效，组合层降仓有效**（2026-09-11）

全部在**无前视滚动池**（`R300_dyn` 场景）上测试，基线 = 年化 8.30% / 夏普 0.287 / 回撤 **-51.83%** / Calmar 0.160。

#### 6.12.1 E7：单票止损 —— **几乎完全无效**

| 实验 | 规则 | 年化 | 夏普 | 最大回撤 | 换手 |
|---|---|---|---|---|---|
| BASE | 无止损 | 8.30% | 0.287 | -51.83% | 26.61% |
| SF1 | 固定止损 -15% | 8.36% | 0.290 | **-51.83%** | 26.67% |
| SF2 | 固定止损 -25% | 8.30% | 0.287 | **-51.83%** | 26.61% |
| ST1 | 移动止损 -15% | 8.54% | 0.299 | -51.28% | 26.72% |
| ST2 | 移动止损 -25% | 8.26% | 0.285 | -52.05% | 26.63% |
| **SP1** | 组合回撤 -20% → 暴露减半 | 7.01% | 0.282 | **-38.77%** | 17.98% |

**结论**：**四种单票止损对回撤几乎零作用**（-51.83% 分毫未动，ST1 仅改善 0.55pp）。

**根因**：
1. 策略本身已有退出规则（跌破均线 / 动量恶化 / 估值过高 / 动量转负），**已起到止损功能** → 再加止损无增量；
2. 更关键：**-51.83% 的回撤来自系统性下跌**（市场整体下挫时全部持仓一起跌），
   单票止损只能"卖出后再买回"，反而增加成本，无法改变组合层面的暴露。

#### 6.12.2 E8：市场层 vs 组合层风控

**触发 E8 的发现**：引擎在 `regime_scope='stock'` 时 `expo` **恒为 0.9** ——
**个股级 regime 只做入场筛选，完全没有市场层面的仓位管理**。这是 -51.83% 回撤的机制性根因。

| 实验 | 规则 | 年化 | 夏普 | 最大回撤 | 空仓 | Calmar |
|---|---|---|---|---|---|---|
| **BASE** | 无风控 | 8.30% | 0.287 | -51.83% | 0% | 0.160 |
| MB1 | 熊市半仓（上证 MA56 之下 → 0.5） | 7.53% | 0.258 | **-51.71%** | 0% | 0.146 |
| MB2 | 熊市空仓（→ 0.0） | 6.46% | 0.210 | **-51.64%** | 32.6% | 0.125 |
| SP1 | 组合回撤 -20% → 减半 | 7.01% | 0.282 | -38.77% | 0% | 0.181 |
| **SP2** | **组合回撤 -15% → 减半** | **6.58%** | **0.274** | **-35.29%** | 0% | **0.186** |
| BEST | 熊市半仓 + 组合 -20% 减半 | 6.27% | 0.245 | -38.69% | 0% | 0.162 |

**两个结论**：

**① ❌ 市场择时（MA56）无效 —— 滞后太严重**

MB2 让 32.6% 的时间处于空仓，回撤**仅从 -51.83% 改善到 -51.64%**（0.19pp），
代价是年化损失 **1.84pp**、夏普从 0.287 掉到 **0.210** → **净负贡献**。
原因：MA56 是滞后指标，指数跌破 1 年均线时组合已完成大部分下跌。

**② ✅ 组合层降仓有效 —— 因为它反应更快**

组合自身回撤比指数均线**更早**感知风险。`-15% 减半` 使回撤 **-51.83% → -35.29%（改善 16.5pp）**，
年化仅损失 1.72pp，**夏普几乎不变（0.287→0.274）**，**Calmar 0.160 → 0.186（+16%）**。

#### 6.12.3 阈值扫描（找甜点）

| 组合降仓阈值 | 年化 | 夏普 | 最大回撤 | Calmar |
|---|---|---|---|---|
| -10% | 5.05% | 0.194 | -35.29% | 0.143 |
| **-15%** | **6.58%** | **0.274** | **-35.29%** | **0.186** |
| -20% | **7.01%** | **0.282** | -38.77% | 0.181 |
| -25% | 5.55% | 0.192 | -43.16% | 0.129 |
| -30% | 7.00% | 0.256 | -43.16% | 0.162 |

**-15% 是最优**：Calmar 最高（0.186）。
- 阈值过紧（-10%）→ 年化损失过大（降到 5.05%）；
- 阈值过宽（-25%/-30%）→ 触发太晚，回撤反而恶化到 -43%。

#### 6.12.4 诚实结论

| 目标 | 结果 |
|---|---|
| 回撤压到 **-30% 以内** | ❌ **未达成**（最优 -35.29%） |
| 回撤显著改善 | ✅ **达成**（-51.83% → -35.29%，+16.5pp） |
| 年化损失 < 2pp | ✅ 达成（-1.72pp） |
| Calmar 提升 | ✅ **+16%**（0.160 → 0.186） |

**两个实现踩坑**（已修正，值得记录）：

| 坑 | 现象 | 解法 |
|---|---|---|
| `regime_fn(None, bd)` 不支持 | `seg_index_for` 抛 `AttributeError: 'NoneType' object has no attribute 'startswith'` | B 方案是"**分市场**"，入参须为个股代码。改用**独立的市场状态序列**（`_market_up_series`，上证 vs MA56）由 bridge 预计算后传入 |
| `_load_prices()` 的 `close` 是**字典** | `close[i-ma]` 抛 `KeyError: 0` | 它是 `{日期: 价格}` 映射（引擎里用 `meta[code]['c'][meta[code]['d'][ti]]` 取值），须 `[cmap.get(d) for d in dates]` 转为序列 |

#### 6.12.5 建议

| 优先级 | 动作 | 预期 |
|---|---|---|
| **P0** | **上线「组合回撤 -15% → 暴露减半」** | 回撤 -51.83% → -35.29%，Calmar +16%，改动极小（引擎约 5 行 + 参数） |
| P1 | 尝试**分档降仓**（-10%→70%、-20%→40%、-30%→20%） | 有望进一步压到 -30% 以内，需再测 |
| P1 | 尝试**降仓比例调参**（-15% 时降到 30% 而非 50%） | 同上 |
| ❌ | **不做**单票止损（E7 证明无效）、**不做**均线择时（E8 证明负贡献） | — |

**新增产物**：
- 引擎：`stop_fixed` / `stop_trail` / `stop_port` / `bear_expo` / `market_up_series` 参数（约 15 行）
- bridge：`_market_up_series()`、`compare_stops()`、`compare_risk()`
